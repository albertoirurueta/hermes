# Implement one task-group bucket (React Native)

Carry out every React Native task in one plan-group bucket end to end: one quality baseline up front, implement each
task (in parallel where safe), then validate everything the bucket touched in a single consolidated pass instead of
once per task.

It is built on the same TypeScript gate skills as `iru-typescript-code-one-task-group` — `iru-typescript-test`,
`iru-typescript-coverage`, `iru-typescript-code-quality`, and `iru-typescript-tsdoc`, which recognize both React
Native toolchains (Jest preset `jest-expo` vs `@react-native/jest-preset`, `eslint-config-expo` vs
`@react-native/eslint-config`, and an `e2e` selector for Maestro/Detox) — each invoked through an `iru-gate-runner`
agent so its report never lands in this context. Fall back to the explicit command shown only when a skill isn't
installed in the consuming repository.

Four things differ from the plain TypeScript group skill, and they shape the validation order:

1. **Native code has its own gates — and the toolchain decides who owns it.** In a **metro** app, `android/` and
   `ios/` are committed source: a bucket that touched them must leave both building, so Steps 3.7–3.8 build the side
   it touched. In an **expo** app they are generated by `npx expo prebuild` and must never be edited — Step 3.9
   validates config-plugin changes by generating native projects in a throwaway copy instead. (Expo bundles with
   Metro too; `metro` names the toolchain without the Expo framework.)
2. **The coverage gate is measured from Jest unit tests alone.** Maestro/Detox drive a real app on a device and
   produce no source coverage; native JUnit/XCTest cover Kotlin/Swift, not the TypeScript the gate measures. A file
   reachable only end to end is a finding, not a pass.
3. **Type-checking is its own gate.** Both Jest presets transform TypeScript with Babel, which strips types without
   checking them; `tsc --noEmit` (inside `iru-typescript-code-quality`) is the only check that sees a type error in a
   test or in a platform file (`Foo.android.tsx`) Jest never resolves.
4. **The e2e stage needs a device, a build, and Metro — and only one run may hold them.** It always runs last,
   serialized behind the repository-wide lock (Step 0, Step 3.10a).

It uses a medium model on purpose: the plan carries the hard reasoning; this skill drives execution of it.

Agent dispatch: call the catalog agents as `subagent_type: "<agent-name>"` (for example `"iru-gate-runner"`) when installed under `.claude/agents/`, or as `"iru-core:<agent-name>"` when installed as a plugin — use whichever name appears in your available agent types. Every `subagent_type` below is written in the first form.

## Step 0 — Read this before running anything on a device

**Only one device-bound run may be in flight against this repository at any moment.** A Maestro or Detox run, or an
`xcodebuild test`, drives a booted simulator/emulator and (for debug builds) talks to the Metro server on port 8081.
Two of them at once install over each other's app, share one Metro (serving whichever project started it), tap on
each other's screens, and produce failures nothing in the code explains — or passes that only happened because the
other run left the app in the right state. That is why this is a hard rule, not a performance note.

This applies at three levels:

1. **Across buckets/groups** — enforced by the lock in Step 3.10a, regardless of what the caller does. The lock
   directory is the same `.integration-test.lock` at the **repository root** (`git rev-parse --show-toplevel`) every
   other group skill in this catalog uses (`iru-java-springboot-code-one-task-group`, `iru-nestjs-code-one-task-group`,
   `iru-nextjs-code-one-task-group`, …), so a polyglot repository serializes all of them together. Run every lock
   command from the repository root.
2. **Within this bucket** — Step 2's per-task agents never run tests, builds, Metro, or flows (the per-task skill
   forbids it), so the only device-bound run is Step 3.10's.
3. **Within the run** — never shard flows across devices, never add parallelism flags, never run Android and iOS
   e2e in parallel agents.

Native **builds** (Step 3.7's Gradle build, Step 3.8's `xcodebuild build`, Step 3.9's prebuild check) boot nothing
and need no lock.

## Step 1 — Detect the profile once, then capture one pre-change quality baseline

Detect once, from the app root (the directory whose `package.json` has `react-native`; in a monorepo, the app package
the bucket's tasks name), and reuse for every step below:

- **Toolchain** — `expo` in `dependencies` → **expo** (even when `android/`/`ios/` exist: prebuild output);
  `react-native` without `expo`, plus `metro.config.js` / committed `android/` + `ios/` /
  `@react-native-community/cli` → **metro**. If the bucket mixes tasks for two apps, run this skill once per app.
- **Jest** — preset (`jest-expo`/`jest-expo/<platform>` or `@react-native/jest-preset`, legacy `react-native`), config
  location (`jest.config.js` or the `package.json` `jest` key), `test`/`coverage` scripts, and the
  `@testing-library/react-native` major.
- **Package manager** — `packageManager`, else the lockfile (`package-lock.json` → npm, `pnpm-lock.yaml` → pnpm,
  `yarn.lock` → yarn, `bun.lock` → bun).
- **Lint/format/type-check** — the `lint`, `format`, `typecheck` scripts (ESLint `@react-native/eslint-config` or
  `eslint-config-expo`, Prettier, `tsc --noEmit`).
- **Native sides (metro)** — `android/gradlew` (Gradle root is `android/`, app module `:app`), `ios/Podfile`, the
  workspace and scheme (`ios/<AppName>.xcworkspace`, scheme `<AppName>` — `app.json` `name`), whether a `Gemfile`
  pins CocoaPods (`bundle exec pod install`), whether native test sources exist (`android/app/src/test/`, an
  `<AppName>Tests` target).
- **Expo native config (expo)** — `app.json`/`app.config.*` and its `plugins`, local config plugins
  (`plugins/**`, `app.plugin.js`), local Expo modules (`modules/*/expo-module.config.json`).
- **E2E** — Maestro (`.maestro/*.yaml`, `maestro --version`) or Detox (`.detoxrc.*`, `e2e/`); the project's own e2e
  scripts (`e2e`, `e2e:ios`, `e2e:android`, `test:e2e`) and how they build/install the app; or none.
- **Host capabilities** — `uname -s` (iOS stages need macOS), `xcode-select -p` pointing into `Xcode.app` (not just
  Command Line Tools), `JAVA_HOME` on JDK 17+ and `ANDROID_HOME`/`ANDROID_SDK_ROOT` or `android/local.properties`
  (Android stages fail at configuration time without them — that's an environment problem, not a code defect).

Then collect the files every task in the bucket is expected to touch and capture a single pre-change baseline via
`iru-gate-runner`:

```
Agent({
  description: "Capture pre-change quality baseline for task group",
  subagent_type: "iru-gate-runner",
  prompt: "Invoke Skill({skill: \"iru-typescript-code-quality\", args: \"<file1,file2,...>\"}) in the React Native
    app at <app root> (<expo|metro> toolchain). Report back only the per-rule-id issue counts (and the issues) for
    these files, grouped by tool (ESLint, tsc, Prettier).",
  run_in_background: false
})
```

If the bucket's tasks name files under `android/` (metro), also capture an Android Lint baseline the same way —
`iru-android-code-quality` with `module: app` **only if** that skill's Step 0 accepts a Gradle-root/project-directory
input pointing at `android/` (it assumes `./gradlew` at the repository root otherwise); else run `./gradlew
:app:lintDebug` from `android/` through `iru-gate-runner` and record the issue ids from
`android/app/build/reports/lint-results-debug.xml`. Record everything as this bucket's baseline — empty if every file
is new. Skip a baseline whose gate skill isn't installed, and say so in Step 5.

Don't touch the lock here — it is acquired in Step 3.10a, immediately before the run that needs it.

## Step 2 — Implement each task via `iru-react-native-code-one-task`

- **Bucket marked `Parallelizable: yes`**: issue all the `Agent` calls together, in the same response:
  ```
  Agent({
    description: "Implement <task N> via iru-react-native-code-one-task",
    subagent_type: "iru-isolated-skill-executor",
    prompt: "Invoke Skill({skill: \"iru-react-native-code-one-task\", args: \"<the task's full text, including its
      exact implementation_plan.md checkbox line(s) for itself and its sub-tasks, its sub-tasks' own text, and any
      relevant Current code state context>\"}). Report back: the detected toolchain, the files touched grouped as
      JS/TS, native and config, the tests added/updated (Jest, native, Maestro/Detox) — none run — the native impact
      (which platform changed, whether pod install / a Gradle build / a development build / a prebuild check is
      needed, OTA-compatible or not), any deviation from the skill's reference/, and whether the task stopped on a
      blocker. Do not run Jest, tsc, ESLint, Gradle, CocoaPods, xcodebuild, Metro, expo prebuild or any e2e flow:
      sibling agents run concurrently and the group's device stage is serialized behind a repository-wide lock.",
    run_in_background: false
  })
  ```
- **Bucket marked `Parallelizable: no`**: invoke them one at a time in the plan's order, waiting for each.

**One ordering constraint React Native imposes regardless of the verdict**: tasks that edit the same navigator/layout
file (`_layout.tsx`, the root stack), the same native registration point (`MainApplication.kt`, `AppDelegate`,
`Podfile`, `app.json` `plugins`, `package.json` `codegenConfig`), or where one task's spec/facade is used by another,
must run sequentially (spec/provider first) — parallel edits to one config object or registration list clobber each
other. Check for that before fanning out; if the group is marked parallelizable, run just those tasks sequentially
and note the deviation in Step 5.

As each agent reports back, re-read `implementation_plan.md` and confirm its box is checked; if not (a concurrent-
write race), flip it yourself with the same "group validation pending" note. Notify the user that this task's
implementation and tests landed. A task that stopped on a blocker is recorded and excluded from Step 3's validation,
without blocking the rest of the bucket.

## Step 3 — Validate the whole bucket once

Derive the validation scope first: the union of the files each agent reported, cross-checked against a fresh
`git status`, `git diff --name-only`, and `git diff --name-only --cached`. Split it into **JS/TS** (everything Jest,
ESLint, `tsc`, and Prettier see), **Android** (`android/**`), **iOS** (`ios/**`), and **Expo native config**
(`app.json`/`app.config.*`, `plugins/**`, `modules/**`, `package.json` `codegenConfig`). Also note the bucket's **UI
scope**: every screen and component (`.tsx` under `app/`, `src/**/screens/`, `src/**/components/`, or anything the
agents' reported `Screen › Region › Component` trees name) added or changed, with the visual states its
`*.fixtures.ts` / gallery registry entry declares — Step 3.11 checks captures for exactly these. **Expo guard**: if the
toolchain is expo and anything under `android/` or `ios/` appears in the diff, that is a defect — revert it via the
task that made it (moving the change into app config / a config plugin / a local Expo module) before going on.

Then run, in this order — cheapest first; **3.1–3.9 gate the bucket, 3.10 runs only once they pass, and 3.11 checks the UI evidence 3.10 produced**:

1. **License headers**, via `iru-gate-runner`: `Agent({description: "Add license headers for task group",
   subagent_type: "iru-gate-runner", prompt: "Invoke Skill({skill: \"iru-check-license\", args:
   \"<file1,file2,...>\"}) scoped to every file this bucket's tasks added or modified (TS/TSX, Kotlin/Java,
   Swift/Obj-C/Obj-C++, config plugins). Report back only which files were missing a header vs. fixed vs. already
   compliant, and — if no header convention existed anywhere in the repo — whether the user chose to skip or generate
   one."})`. Respect a skip choice for the rest of the run. Skip if `iru-check-license` isn't installed.

2. **TSDoc**, via `iru-gate-runner`: `Agent({description: "Update TSDoc for task group", subagent_type:
   "iru-gate-runner", prompt: "Invoke Skill({skill: \"iru-typescript-tsdoc\", args: \"<TS/TSX source files only — no
   tests, no Maestro/Detox flows>\"}) in this React Native app (<expo|metro>). Report back only which exported symbols
   (components and their props interfaces, hooks, native-module facades and specs, utilities, types) were documented
   or completed, and whether the doc-build verification (TypeDoc, if configured) passed or the run was audit-only."})`.
   Fix and re-invoke until any configured doc build passes. Skip if `iru-typescript-tsdoc` isn't installed.

3. **Scoped unit tests**, via `iru-gate-runner`: `Agent({description: "Run unit tests for task group",
   subagent_type: "iru-gate-runner", prompt: "Invoke Skill({skill: \"iru-typescript-test\", args: \"<the Jest test
   files affected by this bucket, space-separated>\"}) in this React Native app (unit suite only — no e2e selector).
   If that skill isn't installed, run `npx jest <files>` (the project's preset — jest-expo or
   @react-native/jest-preset — applies automatically). If everything passes, report back only that. If anything
   fails, report back only the failing test names, the failure reason, and the assertion message for each."})`. Trace
   any failure to its task, fix, and re-invoke until green. Jest exits 0 when a pattern matches no file — confirm the
   reported test count is non-zero for a bucket that added tests.

4. **Unit-test coverage — the 80% gate**, via `iru-gate-runner`:
   ```
   Agent({
     description: "Check unit-test coverage for task group",
     subagent_type: "iru-gate-runner",
     prompt: "Invoke Skill({skill: \"iru-typescript-coverage\", args: \"<selector covering the bucket's Jest tests,
       plus every TS/TSX source file this bucket changed or added>\"}) in this React Native app. Measure the Jest UNIT
       suite only — never Maestro/Detox, never native tests. Exclude Codegen spec files (specs/Native*.ts,
       *NativeComponent.ts), type-only files, Expo Router route files that only compose feature components, and
       app entry files (index.js, App.tsx in a metro app). If the skill isn't installed, run `npx jest <selector>
       --coverage --coverageReporters=json-summary --coverageReporters=lcov --collectCoverageFrom='<each target
       file>'` and read coverage/coverage-summary.json (coverage/lcov.info is the shared lcov path). Report back, per
       target file, its line and branch coverage percentage and its uncovered line ranges, and confirm the run was
       unit-only.",
     run_in_background: false
   })
   ```
   **Gate: every changed/added TS/TSX source file at ≥ 80% line coverage, and ≥ 80% branch coverage.** For a
   shortfall, add **unit** tests via the task that owns the file, re-run 3.3, and re-check here. Platform files Jest
   doesn't resolve under the preset's default platform (`Foo.android.tsx` under an iOS-default preset) show as
   unexecuted unless a test imports them directly — test them that way rather than excluding them. **An e2e flow or a
   native test never closes the gap**; a file reachable only on a device is either unit-tested through an extracted
   module or recorded in Step 5 as an accepted exception with the reasoning.

5. **Full unit suite**, via `iru-gate-runner`: `Agent({description: "Run full unit test suite", subagent_type:
   "iru-gate-runner", prompt: "Invoke Skill({skill: \"iru-typescript-test\"}) with no selector in this React Native
   app (unit suite only), or run the project's `test` script (`npm test` / `pnpm test` / `yarn test`) if the skill
   isn't installed. Never the e2e suite. If everything passes, report back only that; otherwise only the failing test
   names, reasons, and assertion messages."})`. Fix regressions and re-invoke until green.

6. **Code quality — lint, type-check, format**, diffed against Step 1's baseline, via `iru-gate-runner`:
   `Agent({description: "Check for new quality issues in task group", subagent_type: "iru-gate-runner", prompt:
   "Invoke Skill({skill: \"iru-typescript-code-quality\", args: \"<file1,file2,...>\"}) in this React Native app —
   ESLint with the project's config (@react-native/eslint-config or eslint-config-expo, whichever the lint script
   runs), `tsc --noEmit` over the whole project (it includes tests and every platform file), and Prettier. Exclude
   generated code (.expo/, android/app/build/, ios/build/, ios/Pods/). Compare against this pre-change baseline:
   <baseline from Step 1>. Report back only newly appearing issues, each with tool, rule id, file, and line."})`. Any
   new issue is a defect this bucket introduced — trace it to its task, fix it, re-run 3.3 and 3.5, and re-check.
   Treat **every `tsc` error as blocking**, including those in tests and platform files: Jest never reported them.
   `react-native-a11y/*` rule ids are the automated accessibility check: read `accessibility` from `.ui-quality.yml`
   at the repository root (missing file = `enforce`) — with `enforce` a new one is a defect like any other; with
   `report` list them for Step 5 and don't fix-loop on them; with `off` the project's ESLint config has the rules
   off (`iru-setup-react-native-app`'s config reads the same file). On
   an expo app with typed routes, a `tsc` error about missing `.expo/types` on a clean checkout is a missing type
   generation (`npx expo customize tsconfig.json` / a first `expo start`), not a code defect — report it as an
   environment note rather than casting it away. Leave an issue in place only if fixing it would contradict what its
   task explicitly specifies, and record why. Skip if `iru-typescript-code-quality` isn't installed — and then run
   `npx tsc --noEmit` through `iru-gate-runner` anyway, because nothing else type-checks.

7. **Android native stage — metro only, and only when the bucket touched `android/`** (or added a native dependency /
   Codegen spec that changes the Android build). Via `iru-gate-runner`:
   ```
   Agent({
     description: "Build and test Android native code for task group",
     subagent_type: "iru-gate-runner",
     prompt: "In the React Native app at <app root>, the Gradle root is android/ (not the repository root). If
       iru-android-code-quality / iru-android-test accept a Gradle-root/project-directory input, invoke them with
       module: app and that directory; otherwise run, from android/:
       `./gradlew lint testDebugUnitTest assembleDebug -PreactNativeArchitectures=<host ABI, e.g. arm64-v8a>`
       (JAVA_HOME on JDK 17+, ANDROID_HOME set). Report back only: success or each error with file, line and
       message; Android Lint issues newly appearing versus this baseline: <Android Lint baseline from Step 1, or
       'none captured'> (read android/app/build/reports/lint-results-debug.xml); and failing JVM unit tests with
       name, reason and first stack-trace line (android/app/build/test-results/testDebugUnitTest/*.xml). Classify any
       failure as code vs environment (JDK, SDK location, NDK/CMake missing, network).",
     run_in_background: false
   })
   ```
   Restricting `reactNativeArchitectures` to the host ABI keeps the native (CMake/Codegen) part of the debug build to
   one ABI; drop the flag if the project pins architectures itself. A first run downloads Gradle, the React Native
   Android artifacts, and builds C++ for the autolinked Codegen output — minutes, not a hang. Fix code failures via
   the owning task and re-run; report environment failures as **Android native stage unverified (<cause>)**.

8. **iOS native stage — metro only, only when the bucket touched `ios/`** (or added a native dependency / Codegen
   spec), and only on macOS with a full Xcode (`xcode-select -p` inside `Xcode.app`) — otherwise report **iOS native
   stage unverified (no macOS/Xcode)** and continue. Via `iru-gate-runner`:
   ```
   Agent({
     description: "Build iOS native code for task group",
     subagent_type: "iru-gate-runner",
     prompt: "In the React Native app at <app root>: run `bundle install` then `cd ios && bundle exec pod install`
       when a Gemfile exists (plain `cd ios && pod install` otherwise), with LANG=en_US.UTF-8 exported (CocoaPods
       aborts on a non-UTF-8 locale) — Codegen runs here — then
       `xcodebuild build -workspace ios/<AppName>.xcworkspace -scheme <AppName> -configuration Debug
       -destination 'generic/platform=iOS Simulator' -derivedDataPath <a temp dir outside the repository>
       CODE_SIGNING_ALLOWED=NO -quiet`. Do not boot a simulator. Report back only success, or each compile/link
       error with file, line and message, and classify failures as code vs environment (CocoaPods/Ruby, missing
       simulator runtime, Xcode version)."
   })
   ```
   This builds; it doesn't run XCTest (that boots a simulator — Step 3.10). `pod install` may rewrite
   `ios/Podfile.lock` and the workspace: keep those changes only when the bucket added/removed a native dependency or
   spec; otherwise restore them with `git diff` review so a validation run doesn't commit unrelated churn. Fix code
   failures via the owning task and re-run.

9. **Expo native-config check — expo only, and only when the bucket changed app config native fields or `plugins`,
   a local config plugin (`plugins/**`, `app.plugin.js`), a local Expo module (`modules/**`), or added a package that
   ships a config plugin.** Never in the working tree — `expo prebuild` there would create/overwrite `android/`/`ios/`
   and rewrite `package.json` scripts. Via `iru-gate-runner`:
   ```
   Agent({
     description: "Check Expo config plugins via prebuild in a throwaway copy",
     subagent_type: "iru-gate-runner",
     prompt: "1) In the app root, run `npx expo config --type introspect --json` and report whether it succeeds and
       whether these expected native keys appear: <keys the tasks said they add, e.g. ios.infoPlist.NSCameraUsageDescription,
       android.permissions entries>. 2) Create a throwaway directory outside the repository (`mktemp -d`), copy the
       app into it excluding node_modules, .git, android and ios (`rsync -a --exclude node_modules --exclude .git
       --exclude android --exclude ios <app root>/ <tmp>/`), symlink node_modules (`ln -s <app root>/node_modules
       <tmp>/node_modules`), and run `CI=1 npx expo prebuild --no-install --platform all` inside it. Report success or
       the plugin error, and grep the generated ios/*/Info.plist, android/app/src/main/AndroidManifest.xml and Gradle
       files for the expected entries. <Only if the bucket changed native sources under modules/:> 3) In that copy,
       run `./gradlew assembleDebug -PreactNativeArchitectures=<host ABI>` from android/, and on macOS with Xcode
       `cd ios && pod install` plus `xcodebuild build -workspace <tmp>/ios/<Name>.xcworkspace -scheme <Name>
       -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO -quiet`, reporting only errors with
       file/line. Never write into the repository; leave the temp directory for the OS to clean."
   })
   ```
   Decision record: the introspect step is cheap and read-only, so it runs whenever app config changed; the full
   prebuild runs only when a *plugin* (package, local plugin, or Expo module) is involved, because only plugins run
   code that can fail; a native compile of the copy runs only when local Expo module native code changed, because
   that is the only Kotlin/Swift an expo bucket can author. A plugin error or a missing expected key is a defect for
   the owning task; a prebuild that needs network/credentials the machine lacks is **unverified (<cause>)**.

10a. **Acquire the repository-wide lock** — immediately before 3.10, never earlier.

   Skip 3.10a–3.10b entirely (no lock, no run) when:

   - **No e2e framework is wired and no native XCTest target is in scope** (Step 1): say so in Step 5 rather than
     reporting a stage that never existed. If this bucket's tasks *wrote* flows but the project has no e2e setup,
     that's a finding to report — and if the bucket touched UI, Step 3.11 reports **UI captures not wired** (no
     `.maestro/ui/` gallery flows / Detox `e2e/support/ui-screenshots.ts`).
   - **No usable device** — Maestro: no booted iOS simulator (`xcrun simctl list devices booted` lists none, or not
     macOS) *and* no Android device/emulator (`adb devices` shows no `device` line); Detox: the simulator/AVD its
     chosen configuration names doesn't exist (Detox boots it itself). Report the stage as **e2e unverified (no
     booted simulator/emulator)** and continue to Step 4. Never create a device or boot one for Maestro to make the
     stage run, and never stop one this skill didn't start.
   - **The e2e tool is missing** (`maestro --version` fails for a Maestro project; Detox CLI absent): **e2e unverified
     (Maestro/Detox not installed)**.

   From the repository root:

   ```bash
   mkdir .integration-test.lock 2>/dev/null && echo ACQUIRED || echo HELD
   ```

   - **`ACQUIRED`** — immediately write `.integration-test.lock/owner` (via the `Write` tool) with this bucket's
     identifying text (task numbers/titles), "React Native e2e (<expo|metro>, <platform>)", the app root, and
     `date -u +'%Y-%m-%dT%H:%M:%SZ'`. Ensure `.integration-test.lock/` is in the repository's root `.gitignore` (add
     the line if missing) — it's transient local state and must never be committed.
   - **`HELD`** — another group is running its integration/e2e stage. Tell the user this bucket is waiting (naming the
     holder from `cat .integration-test.lock/owner` if readable), then re-run the `mkdir` roughly every 30 seconds.
     Don't run a flow anyway, not even "just one".

   Two bounded escapes, so a crashed run can't deadlock the pipeline:

   - **Stale lock** — if `find .integration-test.lock -maxdepth 0 -mmin +60` returns the directory, its holder has run
     for over an hour and almost certainly died. Tell the user what the owner file says, break it
     (`rm -f .integration-test.lock/owner && rmdir .integration-test.lock`), acquire fresh, and say so in Step 5.
   - **Wait timeout** — still held (and not stale) after ~45 minutes of polling: stop waiting, report the stage as
     **e2e unverified — blocked by a concurrent integration run**, continue to Step 4, and name it in Step 5.

10. **E2E** — only now, with everything above clean and the lock held. Pick one platform per run (the one with a
   booted device; iOS first when both are available and the bucket didn't target Android specifically).

   **Make sure the installed app is current first** (Maestro only — Detox builds the app itself in `detox build`).
